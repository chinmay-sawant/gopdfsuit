## Overview

Five parallel reviewers swept Go-only code (`pkg/`, `internal/`, `cmd/`,
`bindings/python/cgo/`, `test/*.go`). This file is the single canonical ledger:
review findings up top, actionable phases below. Each row names the affected
path, the expected behavior, and the proof required to check it off.

Scope notes: frontend, Python wrappers, docs, and sampledata were excluded.
Two agent claims were corrected during verification (see Corrections).

## Executive Summary

- **2 confirmed P0 races/hangs fixes**: image-cache write under `RLock`
  (`internal/pdf/image.go:164-168`, verified in code), plus server hardening
  pair (no graceful shutdown, unbounded request reads).
- **No memory leak** in the Python/Go bridge (separate soak test, flat RSS
  over 6000 ops) but `bindings/python/cgo/exports.go` panics on empty output
  (`&slice[0]`, 13 sites, verified pattern) and trusts caller lengths.
- **Crafted-input panics/hangs are the biggest cluster**: `/W` validation in
  two `parseXRefStreams` copies, SVG path tokenizer, font subset table
  indexes, unbounded inflate in redact/form paths.
- **Good news**: buffer/pool discipline, 32 MiB + 50k-object caps on compress,
  capped inflate in merge/parser and compress/stream, no secret logging, no
  unused direct deps.

## Corrections (agent claims adjusted after source verification)

- C1: `internal/pdf/xref/xref.go` `WriteCompactXRef` missing-else is **dead
  code, not corruption** - `usedObjects` is built from `offsets` keys, so the
  lookup always hits. Kept as P2 defense-in-depth only.
- C2: `internal/pdf/outline.go` title accumulation triggers **only for the
  second and later consecutive non-ASCII titles** (ASCII branch resets).
- C3: `merge.py` ctypes `.raw` temp pattern is **safe today** (ctypes keeps
  the bytes in the array `_objects`); kept as robustness nit, not a bug.
- C4: `pkg/gopdflib` ParsePageSpec empty-spec rejection was **wrong** - the
  established contract (`merge/split.go:21-23`, python `test_empty_spec`)
  is empty spec selects no pages (`nil, nil`). Wrapper aligned to return
  `nil, nil`; boundary test asserts the contract plus `page 0` rejection.
- C5: image-ID fix needed a second pass - moving images to `NextObjectID`
  alone still collided with the dense content/font layout at ~1000 pages
  (content `[N+3, 2N+3)` vs images at 2000+). Closed with
  `layoutContentFontIDs` (shift above extras when needed) plus a fail-closed
  guard past ~1997 pages; proven by `TestShiftedLayoutLargeDoc` (1297 pages,
  all IDs unique).
